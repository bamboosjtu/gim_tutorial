# 视觉系统

> 来源：EP01 成片实测参数（1920×1080 / 20fps）。数值可直接照抄。

## 1 配色：一种颜色只承担一种语义

| 角色 | HEX | RGB | 语义 |
|---|---|---|---|
| 背景 | `#0F172A` | 15,23,42 | 全片底色，**不画网格、不加纹理** |
| 面板 | `#1E293B` | 30,41,59 | 一级卡片底 |
| 面板浅 | `#172136` | 23,33,54 | 二级卡片 / 强调块 |
| 描边 | `#334155` | 51,65,85 | 卡片边框、分隔线 |
| 主文字 | `#E2E8F0` | 226,232,240 | 正文 |
| 次文字 | `#94A3B8` | 148,163,184 | 注释、单位、出处 |
| 青 | `#22D3EE` | 34,211,238 | **结构在哪**：层级、键名、路径、下一跳 |
| 琥珀 | `#F59E0B` | 245,158,11 | **注意这里**：当前指针、易错点、结论 |
| 绿 | `#22C55E` | 34,197,94 | **对上了**：校验一致的数、真实输出 |
| 蓝 | `#2563EB` | 37,99,235 | 进度、已完成状态 |
| 红 | `#EF4444` | 239,68,68 | 仅"这里错了"，一集 ≤2 处 |

**规则**：颜色是语法，不是装饰。观众看两分钟就能建立条件反射——看到青色就去找结构，看到琥珀就放慢速度。

推论：
- 正文说明**不要上色**，一上色就削弱了三种语义色
- 同一屏不要出现四种以上语义色
- 红色要吝啬，用多了等于没用

## 2 字体

| 用途 | 文件 | 说明 |
|---|---|---|
| 标题 / 强调 / 数字 | `C:/Windows/Fonts/msyhbd.ttc` | 微软雅黑 Bold |
| 正文 / 说明 | `C:/Windows/Fonts/msyh.ttc` | 微软雅黑 Regular |
| 代码 / 键名 / 路径 | `C:/Windows/Fonts/consolab.ttf` | Consolas Bold，`=` `.` 对齐 |

**铁律：Consolas 没有中文字形。** 含汉字的字符串（包括 `EP 01 · 线路篇` 这种混排）必须用雅黑，否则中文变豆腐块。

```python
def F(kind, size):   # kind: 'bold' | 'reg' | 'mono'
    ...
```

字重只有两档：Bold（标题、数字）、Regular（一切说明）。**不用斜体、不用细体。**

## 3 字号阶梯

| 层级 | 字号 | 用在哪 |
|---|---|---|
| 章号 | 240 | 章封的 `01`–`05` |
| 章名 | 96 | 「容 器」「层 级」 |
| 页标题 | 54 | 每镜顶部 |
| 大数字 | 42–52 | 499 / 779 / 343 这类主证 |
| 中标题 | 30–38 | 卡片标题、章封提要 |
| 小标题 | 22–28 | 论点句、卡片内标题 |
| **正文** | **17–21** | **最常用 19–21** |
| 注释 | 13–16 | 单位、出处、补充 |
| 极小 | 10.5–13 | 键名标签、行列注 |

实测分布：全片 260+ 处文字，15–28 号占七成。**正文别小于 17**，1080p 在手机上看 15 号已经开始糊。

## 5 七种组件

这一集只有七种组件，新的一集优先复用，别重新发明。

### 5.1 卡片

```
标题（22–28 Bold，主文字色）
键名 / 路径（14–17 Consolas，#94A3B8）
说明（15–19 Regular）
左侧 5 px 色条
```

### 5.2 代码块 / 终端块

- 底色 `#0D1117`（比背景更深一档，靠明度区分层级）
- 行高 30–34，字号 15–20 Consolas
- **指针行琥珀**，注释 `#8B949E`，普通输出 `#C9D1D9`
- 全文照抄时：右上标「共 N 行」，不足一屏时底部标「以上是全文」
- 终端模拟：标题栏 + 三圆点 + 状态栏（当前步 + 样本标识）；内容超一屏后**底对齐滚动**

### 5.3 数字块

大数字（42–52 Consolas Bold）+ 下方单位（13–16 雅黑）。三个以上并排用 300–340 等距。**数字颜色跟语义走**（499 青 / 779 琥珀 / 343 绿）。

### 5.4 对比条

左右两面板等宽，中间 70 空隙，上方各一个 20–24 小标题。**不做箭头指向，靠位置表达对立。**

### 5.5 章封

固定五件套，从上到下：章号 240 → 章名 96 → 提要 30 → 引导语 31（青）→ 进度点 22 + `n / 5`。章名下琥珀短线从中间向两侧展开收束。

### 5.6 时间轴（底部常驻）

**按章分块，不按镜头。**

- 已完成 = 蓝实心；进行中 = 深底 + 蓝色填到光标；未开始 = 更深的灰（`#222C3C`）
- 章内小节 1 px 细线；章间 2 px 亮线 + 7 px 间隙
- 每个章块上方标章名简称，当前章琥珀加粗
- 光标是琥珀圆点
- **时间数字放轴下方右端**——放上方会撞最后一个章名

### 5.7 表格

表头深底白字，隔行 `#1E293B`（视频）/ `#F8FAFC`（PPT）。列宽按内容分配，**首列不许换行**——宁可把「① 耐张段工况」缩成「①」。

### 5.8 连线

**只用正交折线（横平竖直），不用斜线。**

原因：斜线在不同渲染器（PPT、PIL、浏览器）里端点对齐方式不同，容易错位；正交折线即使差几个像素也看得出走向。

- 层级/结构连线：`#94A3B8`，2–3 px
- 多父/强调连线：`#F97316` 或 `#F59E0B`，2 px
- 连接点落在卡片边缘中点，不要落在圆角上
- 需要"汇聚"时用一条横向主干 + 若干竖线接入，比三条斜线汇聚更清楚

四张等宽卡（420 宽），每张：类型名 + 表号 + 必备键 + 数量。

## 7 PPT 与视频的一致性

同一套配色和字号用在两处，但**密度不同**：

- 视频：一屏一个论点，字号大、留白多
- PPT：可以有 5 行表格，字号 13–15

**不一致只允许出现在密度上，不允许出现在配色、术语、数字上。** 定稿前用同一份数字表对一遍。
